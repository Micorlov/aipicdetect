— Self-host

Run the AI image detector on your own machine.

picai is open source. Run it yourself and the pictures you check never leave your computer: no upload, no account, no daily limit, and you can swap the detector model.

One command with Docker

docker run -p 8000:8000 -v picai-models:/data ghcr.io/micorlov/picai:latest

Open http://localhost:8000. The first start downloads the detector model (about 750 MB) into the picai-models volume, so later starts are fast. The status pill in the top bar says Detector ready once the model is loaded.

From source with uv

git clone https://github.com/Micorlov/picai
cd picai
uv sync
uv run picai serve

The server binds to 127.0.0.1:8000 only. To check photos from your phone over Wi-Fi, start it on all interfaces and open your computer's LAN address on the phone:

uv run picai serve --host 0.0.0.0

The page is a small PWA: on a phone it offers Choose photo and Take a photo buttons and can be added to the home screen.

Command line, no browser

uv run picai scrub photo.jpg            # writes photo.clean.jpg with no metadata
uv run picai scrub photo.png --format webp --quality 90
uv run picai inspect photo.clean.jpg    # lists metadata signatures found (or none)
uv run picai batch inbox clean --detect # scrub a folder, score it, write clean/report.json

Configuration

VariableWhat it does
PICAI_DETECTOR_MODELAny Hugging Face image-classification model whose labels name AI/fake vs. human/real content. Defaults to haywoodsloan/ai-image-detector-deploy.
PICAI_DAILY_LIMITAnalyses allowed per client IP per rolling 24 h. Set to 0 to remove the limit on your own instance.
PICAI_PUBLIC_URLPublic origin used in sitemap.xml and canonical links if you put the app behind a domain.
HF_HOMEWhere the model cache lives (the Docker image uses /data/hf).

Requirements

  • About 750 MB of disk for the model and 3 to 4 GB of RAM while it is loaded.
  • CPU is enough; a picture takes a second or two. A GPU is not required.
  • Python 3.12+ and uv when running from source; nothing else when using Docker.

Prefer a batch workflow? The repository ships a GitHub Action: drop images into inbox/, push, and the workflow scrubs and scores each one, commits the clean copies plus a report.json, and shows a results table in the run summary.
