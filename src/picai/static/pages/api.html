— API

AI image detection and metadata scrubbing over HTTP.

Every picai instance exposes a small JSON API. The interactive OpenAPI reference lives at /docs; this page is the short version.

Endpoints

RoutePurpose
POST /analyzeScore an image and list its metadata blocks. Also prepares a scrubbed copy for download.
POST /scrubReturn a re-rendered copy of the image with every metadata block removed. Nothing is scored.
GET /download/{id}Fetch the scrubbed copy prepared by /analyze. Kept in memory only, for the last 100 results.
GET /statusModel name and whether it is loaded.
GET /ready200 once the model is loaded, 503 before. Use it as a readiness probe.

Analyze an image

curl -F "file=@photo.jpg" https://YOUR-INSTANCE/analyze

The response carries the detection result, the metadata blocks found in the upload, and a link to the clean copy:

{
  "detection": {
    "ai_likelihood": 0.97,
    "percent": 97,
    "confidence": "High",
    "classification": "AI",
    "model": "haywoodsloan/ai-image-detector-deploy"
  },
  "metadata": {
    "removed": { "EXIF": ["Exif\\0\\0"], "XMP": ["http://ns.adobe.com/xap/1.0/"] },
    "jpeg_app_segments": ["APP1", "APP1"]
  },
  "input":  { "bytes": 412880, "width": 1600, "height": 1200, "format": "JPEG" },
  "output": { "bytes": 398112, "format": "JPEG", "media_type": "image/jpeg" },
  "download_url": "/download/3f9c…",
  "download_name": "photo.clean.jpg",
  "quota": { "limit": 10, "remaining": 9, "window_hours": 24 }
}

classification is one of AI, Real or Uncertain; confidence is High, Medium or Low. Treat it as a probability, not a verdict: see how accurate is it?

Scrub only

curl -F "file=@photo.jpg" -o photo.clean.jpg https://YOUR-INSTANCE/scrub
curl -F "file=@photo.png" -o photo.clean.webp "https://YOUR-INSTANCE/scrub?format=webp&quality=90"

The clean file comes back as the response body with a Content-Disposition filename and an X-Picai-Removed header listing the blocks that were dropped (for example C2PA,EXIF,XMP).

Parameters and limits

  • format: jpeg, png or webp. Defaults to the input format.
  • quality: 1 to 100 for lossy formats. Defaults to 92.
  • Uploads up to 50 MB; JPEG, PNG, WebP, HEIC/HEIF and anything else Pillow can decode. Unsupported input returns 415.
  • The public instance allows 10 analyses per client IP per rolling 24 hours and answers 429 with a Retry-After header after that. Self-host to remove the limit.

Images are processed in memory. The public instance never writes an upload to disk; the scrubbed copy is held in memory briefly so the browser can download it, then evicted.
