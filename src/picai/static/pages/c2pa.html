C2PA content credentials: check them, then decide.

Content Credentials are the provenance labels that Adobe tools, OpenAI's image models, some Leica and Sony cameras and a growing list of apps embed in the files they produce. picai shows you whether a picture carries them, and can hand back a copy without them.

What C2PA actually is

The Coalition for Content Provenance and Authenticity (C2PA) defines a signed manifest that travels inside the image file. It records who created or edited the picture, with which tool, and whether an AI model was involved. In a JPEG the manifest lives in APP11 segments (a JUMBF box); PNG and WebP carry it in their own chunks. Editors often add a matching note in XMP as well.

Two things follow from that design:

  • Presence is a hint, not proof. A manifest that says "generated with DALL·E" is strong evidence. A manifest that says "exported from Photoshop" tells you nothing about where the pixels came from.
  • Absence proves nothing. Any re-save, screenshot, or messaging app that re-encodes the picture drops the manifest. Most AI images circulating online have already lost it, which is why pixel-level detection still matters.

What picai shows

After you check a picture, the Metadata card lists each block the file carries: EXIF, XMP, IPTC, C2PA and ICC, with the byte signatures it matched, plus every JPEG APP segment. Read it next to the AI likelihood score, not instead of it. A high score with a C2PA manifest naming a generator is about as sure as this gets; a high score on a file with no metadata at all is a probability and nothing more.

Removing C2PA and other metadata

Sometimes you want a clean file: a photo with GPS coordinates you would rather not publish, or an export whose editing history is nobody's business. picai does not edit the container in place. It decodes the picture, applies the EXIF orientation, builds a brand-new image from the raw pixel buffer and encodes that. The new file never sees the original container, so every block goes: C2PA, EXIF, XMP, IPTC and the ICC profile alike.

  • In the browser: check the image, then use Download clean copy under the metadata list.
  • From the command line: picai scrub photo.jpg writes photo.clean.jpg. picai inspect confirms nothing is left.
  • Over HTTP: POST /scrub returns the clean file directly. See the API page.

Dropping the ICC profile can shift colours slightly on wide-gamut images. If colour accuracy matters more than a clean file, keep the original for print and use the scrubbed copy for the web.

When stripping is the wrong call

Content credentials exist so that readers can trust what they see. If you are publishing your own work, keeping the manifest is a feature. Removing a manifest from someone else's image to pass it off as something it is not is exactly the misuse the standard was designed to expose, and a detector like this one is part of how it gets caught.
